Chapter 02 — Activity Guide

Build an Idea Capture Board

Learn arrays, objects, filtering, and dynamic list rendering by building a tool for collecting and organizing ideas in real time.

Why This Project?

Chapter 01 stored a single piece of information — one intention. Chapter 02 levels that up by teaching you how to manage collections of data. Instead of one saved string, you now have many ideas, each with multiple properties.

This is where apps start to feel real. The second you move from one value to a list of structured values, you unlock dashboards, task boards, CRMs, note apps, playlists, shopping carts, and almost every useful interface on the web.

Arrays

Store multiple items in order. Your idea board is powered by an array of idea objects.

Objects

Each idea contains related properties like text, type, tag, and timestamp.

filter()

Show only ideas that match a chosen type or search term.

map()

Turn raw JavaScript data into visible HTML cards on the page.

The AI Angle

When you prompt AI for a project like this, you're no longer just describing visuals or a single behavior. You're describing a data model. That means you have to think in terms of what each item is made of and how the interface should react when the data changes.

This is a major shift: instead of saying "make this look cooler," you're saying "each idea should be an object with these properties, stored in an array, then filtered by type and search term." That's software thinking.

“Once you can describe the data, you can describe the app.”

That’s why this chapter matters. It trains you to think like a builder, not just a user.

Before You Build

Decide what kind of ideas your board should hold before you open AI. Answer these first:

  1. What kinds of ideas do you capture most often — content, features, questions, business ideas, story ideas?
  2. What properties should every idea have? Just text, or also category, tag, date, priority?
  3. How should ideas be sorted — newest first, oldest first, grouped by type?
  4. What actions should each card allow — delete, duplicate, edit, archive?
  5. What would make this board more useful than your phone notes app?

These answers are your spec. You’re teaching AI the shape of your app by first defining it for yourself.

Build It

Phase 1

Set up the layout

Ask AI for a two-column interface: capture controls on the left, idea cards on the right. Keep the aesthetic consistent with the earlier chapters.

Build a single-page idea board in vanilla HTML, CSS, and JavaScript.
Use a dark layout with white text and red accents. The left side should
have a textarea, a type dropdown, a short tag input, and buttons to add
or clear ideas. The right side should display idea cards in a responsive grid.
Phase 2

Create the data structure

Your app needs an array. Each new idea should become an object inside it. This is the heart of the chapter.

Create a JavaScript array called ideas. When the user adds an idea,
push a new object into the array with these properties: id, text,
type, tag, and createdAt. Then save the array to localStorage.
Load it again when the page opens.
Phase 3

Render cards dynamically

Now the board needs to read the array and turn it into visible HTML. This is where map() becomes practical.

Render the ideas array into a card grid. Each card should show the tag,
the type, the idea text, and the time it was created. Use map() to build
the HTML and inject it into the board container.
Phase 4

Add filtering and search

Once a list exists, users need a way to narrow it down. This is where filter() stops being abstract and starts feeling useful.

Add a type filter dropdown and a live search input. Show only ideas that
match the selected type and search term. Search should look through the
idea text, tag, and type. Update the board live as the user types.
Phase 5

Add card actions

Give each idea card at least two actions. In this version, duplicate and delete make the data logic very clear.

Add Duplicate and Delete buttons to each idea card. Delete removes the
matching object from the array. Duplicate creates a new object based on
the original with a new id and current time, then adds it to the top
of the array.

Concepts You Just Used

  • let ideas = [] — stores a growing collection of notes.
  • ideas.unshift(obj) — adds new ideas to the top of the board.
  • ideas.filter(...) — narrows the array based on conditions.
  • ideas.map(...) — transforms objects into HTML strings.
  • JSON.stringify() and JSON.parse() — save and load arrays from localStorage.
  • array.find() — locate a single object to duplicate.
  • array.filter() again — remove one object by keeping all the others.

This is one of the biggest thresholds in JavaScript. Once you understand arrays of objects and how to render them, you can build almost every data-driven interface that matters.

Reflect

  1. What was harder to describe to AI: the visual layout or the data behavior?
  2. When did you first realize your board was really just an array being rendered?
  3. Which action made the logic clearest — add, filter, duplicate, or delete?
  4. What did AI misunderstand the first time, and how did you fix the prompt?
  5. How would this project change if you stored ideas in Supabase instead of localStorage?

A big part of becoming a strong builder is learning to see the invisible structure beneath the interface.

Go Further

Edit Cards

Let users reopen a card, change the text, and save the updated object back into the array.

Priority System

Add a priority field like low, medium, and high, then sort the board by importance.

Archive View

Instead of deleting ideas, mark them archived and filter them out of the main board.

Color Coding

Change the card border color based on idea type to improve scanning.

Export JSON

Download the full array as a JSON file so students can see the raw data behind the UI.

Drag Sort

Allow ideas to be reordered manually and save the new array order back to localStorage.
